# Real-time Feishu WebSocket Event Routing and Self-Reply Suppression

## Summary

- Added `backend/claude_hub/services/feishu_realtime_events.py` to evaluate incoming `PushedMessage` frames from the personal web-session `msg-frontier` WebSocket stream alongside `/ai` command intake in `FeishuAiPoller`.
- Decoupled WebSocket frame intake (`FeishuAiPoller._handle_frontier_pushed_web_message`) from bounded event metadata/history lookups and sink delivery via an owned background queue/worker (`_enqueue_realtime_event` / `_drain_realtime_event_queue`), ensuring a slow or stalled event sink never delays subsequent `/ai` commands or WebSocket frames. In addition, `FeishuAiPoller._get_or_build_user_client` reuses the `FeishuUserClient` / `FeishuWebUserTransport` instance (and its `_chat_cache` / `_msg_cache`) across WebSocket pushes, and `FeishuRealtimeEventRouter.handle_pushed_message` evaluates `is_at_me` and `matched_urls` before calling `_ensure_chat_metadata`, so ordinary unmentioned non-trigger messages never block the FIFO worker on slow chat metadata lookups ahead of urgent `@me` or watch-group URL events.
- Supported two non-self real-time trigger paths without hardcoding any group names, domains, or IDs:
  1. `@current_user` mentions in any group or P2P chat (via `PushMessagesRequest.messagesAtMe` or rich-text `TAG_AT`, excluding `@all`-only broadcasts).
  2. Configured fault/task URL patterns (`CLAUDE_HUB_FEISHU_WATCH_URL_REGEX` / `CLAUDE_HUB_FEISHU_URL_PATTERNS` / `CLAUDE_HUB_PATROL_ACTIONABLE_HOSTS`, parsed via JSON lists or newline-separated entries without comma splitting so regex quantifiers like `{2,4}` and literal commas remain intact) inside configured priority watch groups (`CLAUDE_HUB_FEISHU_WATCH_CHAT_IDS` / `CLAUDE_HUB_FEISHU_WATCH_CHAT_NAMES` or local runtime JSON settings), even when the current user is not `@mentioned`.
- Added deterministic courtesy/acknowledgement suppression (`is_courtesy_or_ack_only`) and same-chat/same-topic self-reply suppression across the real-time WebSocket hook, `FeishuWebUserTransport.list_messages_page`, `services/dot/events_gateway.py`, and `services/demand_patrol/feishu_triage.py`:
  - Same-second messages compare `position` / `topic_position` (including in `FeishuWebUserTransport.list_messages_page` and `_verify_unanswered_via_client`), and equality without position proof is accepted only for a direct reply to `message_id` (`parent_id == message_id` or `root_id == message_id`).
  - Slow-patrol `_is_answered_by` requires strict `own.created_at > message.created_at` for non-direct replies in the same thread (`own.reply_to != message.message_id`), preventing an equal-timestamp quote of an earlier message from suppressing a new question.
  - When `submit_external_event` returns `False` because the `dedupe_key` is already recorded in `index.sqlite.events` (`has_external_event_receipt`), `_deliver_event` treats the durable duplicate receipt as delivered rather than rejected so handled messages do not enter `failed_delivery` fallback or get re-admitted to patrol.
  - Reuse `FeishuAiPoller._cached_user_client` / `FeishuWebUserTransport` across pushes while refreshing chat metadata via `_ensure_chat_metadata(..., refresh=True)` whenever a message with matched URLs arrives in a chat whose cached name is not yet in `cfg.watch_chat_names` (or when metadata is older than 60s), and removing stale name-to-chat mappings on rename so renamed or newly watched groups are recognized immediately without delaying ordinary non-URL messages.
- Restricted cross-transport deduplication to canonical message IDs / verified aliases (`FeishuWebUserTransport.bind_message_alias` / `bind_sender_alias` / `FeishuRealtimeEventRouter.bind_topic_alias`) or a strictly scoped cross-namespace (`om_` vs Web numeric ID) match that rejects conflicting `om_` aliases, refuses heuristic cross-namespace matching when same-chat/same-second/same-text collisions are detected (`ambiguous=True` via `_mark_collisions` / `note_candidate_batch`), requires verified topic/root identity overlap (`c_tkeys & r_tkeys` or `verified_msg`) when `thread_id` is present, and requires verified sender identity overlap (`c_skeys & r_skeys` via `ou_... <-> web_uid` aliases or `verified_msg`, while still rejecting conflicting display names) so a singleton message from any unverified or different sender never clears a pending fallback or deduplicates against another user's receipt.
- Made slow-patrol duplicate suppression strictly receipt-backed (`filter_unanswered` suppresses `@me` and watch-URL candidates only when `is_message_handled` or `has_owner_replied` holds a receipt, retaining any downtime/backlog questions):
  - `suppress_patrol_when_healthy` defaults to `False` so 20-minute patrol continues scanning uncovered unmentioned P2P DMs, participated threads, and watched groups (`--chat-id <oc_...>` per watched group with bounded multi-page pagination via `_watched_chat_window_messages`, avoiding global `--chat-type group` search starvation).
  - When `suppress_patrol_when_healthy=True` is explicitly opted in, `FeishuRealtimeEventRouter.needs_patrol_fallback` re-enables `feishu_due` whenever an uncovered P2P/thread question arrives or a real-time delivery fails, retaining failed watch-URL/mention records across empty patrols and scoping `acknowledge_patrol_fallback` to recovered candidates with strict cross-namespace identity matching (preventing ordinary-group watch-URL leakage and cross-chat alias overwrites) within the patrol's snapshot generation/time window.

## Coexistence & Cutover with Sibling Branches (`29c6249b` & `15856077`)

- **With `29c6249b` (`feat/dot-notify-ee0ac02a`)**:
  - `29c6249b` adds `events_bridge.py:poll_mentions` (`python -m claude_hub.services.dot.events_bridge mentions`), a 90-second `lark-cli im +messages-search --is-at-me` poller that posts `ExternalEvent(source="feishu", event_type="im.mention", dedupe_key=message_id, severity="urgent")` to `/api/dot/events`.
  - **Gateway-level shared suppression and scope**: `services/dot/events_gateway.py:submit_external_event` enforces `_should_suppress_incoming_feishu_event` and `record_suppressed_external_event` (recording suppressed keys in `index.sqlite.events` with `accepted_at=0.0` so they do not consume the 60/hour source quota). During transition overlap, this guarantees suppression of courtesy/ack-only `@me` mentions, messages with a recorded direct reply to `message_id`, and same-key/aliased messages (where `om_...` is bound in the router or `index.sqlite.events`). Because `29c6249b`'s external `ExternalEvent` payload omits `create_time` / `thread_id` / `reply_to` and Web pushes arrive with numeric `web_msg_id` unless an `om_` alias is bound, unaliased cross-namespace dedupe and timestamp-dependent thread-reply suppression cannot be inferred from `29c6249b`'s payload alone; stopping `events_bridge mentions` once `realtime_stream_healthy=true` is therefore required for clean cutover.
  - **Cutover procedure**: Once the personal web-session (`FeishuAiPoller` + `msg-frontier`) is active (`realtime_stream_healthy=true` in `/api/feishu-ai-command/status`), disable or stop the external `events_bridge mentions` polling daemon so `lark-cli` 90s polling is fully replaced by the sub-second WebSocket stream.
- **With `15856077` (`codex/feishu-ai-image-awareness`)**:
  - `15856077` adds `topic_position` to `WebMessage` and `has_images` to `FeishuUserMessage`. `FeishuRealtimeEventRouter` reads `int(getattr(msg, "topic_position", None) or 0)`, working seamlessly both before and after `15856077` is merged.
