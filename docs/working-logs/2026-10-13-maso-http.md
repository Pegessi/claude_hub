## Evidence and decisions

The existing cowork service runs MASO 0.7.3 on local port 9796. Read the installed
`maso_cowork` and `maso_core` wheel sources alongside its OpenAPI, rather than
assuming an OpenAI or Codex wire protocol:

- `server/app.py`: create, send, status, model, pending deletion, control and SSE.
- `server/plugin.py`: character offsets, snapshots, root lifecycle and tools.
- `runtime_modules/condenser/plugin.py`: archive and in-place context splice.
- `runtime.py`: abort retains broker messages and can re-wake them.

Implemented `MasoHttpSession` and `MasoEventAdapter` behind the existing native
Chat transport/registry/tailer owners. Session creation is lazy, uses the chosen
cwd with `isolation=shared`, and persists the opaque MASO session ID. The service's
model catalog supplies grouped thinking variants and their provider keys.

MASO `turn_end` is an LLM response snapshot; only root `agent_end` completes a
Hub turn. Character offsets deduplicate streamed output, and a final response
repairs a missing suffix. Child lifecycle/tool output remains attributed.
Condensation emits status updates and never replays/replaces Hub display events.
The same MASO session owns compressed model context; Hub does not rebuild it from
the displayed transcript. See [the supported contract](../MASO.md).

Independent review corrected cancellation-generation ordering, removal of owned
pending UUIDs before abort, failed-stop recovery, PUT provider/env changes that
would leave stale transports, and effective-model matching for default variants.
The last review found an SSE disconnect during a pending successful POST; a
generation failure flag now prevents that response from clearing uncertainty.
The reviewer approved the final candidate with no blocking findings.

A delivery sidecar beside the existing event log records only endpoint/session/
message identity and uncertainty, not prompts or credentials. It is written
before POST. MASO offers no cancellation tombstone for a request not yet queued,
so an uncertain send remains blocked across restart after best-effort cleanup.
It never automatically retries the prompt or claims that an idle status proves
the server cannot execute it later.

## Boundaries

Initial capabilities exclude images, Goals, Plan mode, edit-resend and managed
Workspace workers. Real harmful-command confirmations and real automatic
threshold-triggered condensation were not exercised; their event paths were
checked with mocks, and manual condensation/session continuity was exercised
against MASO. Terminal HMR/replay and performance suites were not run because
the raw terminal transport was not changed. Existing standard-suite skips are
not represented as passes. The running primary Hub still uses its current build
until a separately authorized integration/release.
