# 2026-11-19: Feishu Web-Session (`larkweb` / `LarkAgentX`) User-Identity Transport for `/ai`

## Background & Problem

In Feishu OpenAPI, replying in-place as the authenticated user requires the restricted `im:message.send_as_user` permission, and bot tenant fallback (`bot_fallback`) requires a bot to be a member of the chat (which is impossible in 1v1 DMs between two human users and often unavailable in external or restricted group chats).

The internal `lark-desk` / `LarkAgentX` web-session protocol (`suyue.rd/persona-extensions` `extensions/lark-desk/internal/web/*` and `byteapi/persona-plugins` `extensions/lark-bridge/larkx_persona/*`) authenticates via a standard Feishu web QR scan (`POST /accounts/qrlogin/init` and `/accounts/qrlogin/polling`) and communicates with `POST https://internal-api-lark-api.feishu.cn/im/gateway/` using `proto2` `Packet` frames (`X-Command`, `X-Command-Version: 5.7.0`) and `wss://msg-frontier.feishu.cn/ws/v2`. Because the web gateway acts as the signed-in human user, `PutMessageRequest` (`cmd=5`), `PutReactionRequest` (`cmd=25`), `DeleteReactionRequest` (`cmd=26`), `PullFeedCardsRequest` (`cmd=1000`), and `PullMessagesByPositionsRequest` (`cmd=43`) work in **any** 1v1 DM or group chat without `im:message.send_as_user` or a bot in the chat.

## Design & Changes

1. **Native Python Feishu Web-Session Package (`backend/claude_hub/services/feishu_web_session/`)**:
   - `protocol_schema.json` & `codec.py`: Pure-Python `proto2` wire encoder/decoder (`encode`, `decode`, `command_of`) covering the full `lark-desk` gateway command and entity schema (`Packet`, `Frame`, `PushMessagesRequest`, `PutMessageRequest`, `PullMessagesByIdsRequest`, `PullMessagesByPositionsRequest`, `PullChatsByIdsRequest`, `PullChattersByIdsRequest`, `PullChatChattersRequest`, `CheckP2PChatsExistByUserRequest`, `PutChatRequest`, `PullFeedCardsRequest`, `PutReactionRequest`, `DeleteReactionRequest`, `PullThreadsByIDsRequest`, `PullThreadMessagesByPositionsRequest`, `RichText`, etc.) with zero external C/protobuf runtime dependencies.
   - `rich.py`: Rich-text element/block builder (`Node`, `Block`, `rich_text`, `rich_blocks`, `markdown_blocks`, `formatted_out`) and message content extractor (`describe`, `text_of`, `text_without`, `card_text`, `meeting_text`, `system_text`, `extract_text_and_title_from_openapi_content`).
   - `qr.py`: Pure-Python ISO/IEC 18004 Byte-mode QR Code matrix generator (`encode_qr_matrix`, `render_qr_unicode`, `render_qr_svg_data_url`), verified bit-for-bit against Node `qrcode`.
   - `store.py`: `FeishuWebSession` and `FeishuWebSessionStore` with AES-256-GCM encryption at rest, `0600` file permissions, strict secret redaction (`[REDACTED]`) across `repr()`, `str()`, and API/CLI status serialization, plus `import_from_larkx()` for `~/.larkx/credentials.json`.
   - `client.py`: `FeishuWebClient` (QR login `start_login` / `poll_login`, `ticket` validation, 64-bit safe `profile` extraction, cross-tenant cookie redirect propagation, gateway `call`, `send`, `react`, `unreact`, `feed_cards`, `messages_at`, `messages_by_id`) and `FeishuWebFrontierListener` (`msg-frontier` WebSocket frame/gzip push decoding, ACKs, and 30s heartbeats). Post-submit transport/decode errors and empty message IDs on `PutMessageRequest` raise `FeishuDeliveryUncertainError` so `/ai` never duplicates an uncertain reply.
   - `adapter.py`: `FeishuWebUserTransport` (maps web gateway chats, topic/thread messages, reactions, and replies to the `FeishuUserClient` contract, resolves OpenAPI `oc_...` / `om_...` aliases to numeric web IDs, deduplicates cross-namespace commands arriving via both bot events and web polling/WS, keeps 1v1 P2P DM replies in the main DM stream while respecting thread mode in groups/topics) and `FeishuWebLoginManager` (with generation tracking and in-flight QR poll cancellation on logout).
   - **Review Cycle-2 & Cycle-3 Hardening**:
     - **Owner Identity Isolation (`R1`)**: `is_web_session_authorized_for_owner()` and `matches_authorized_owner_sender()` enforce strict owner/tenant verification so an unrelated or unverified web session never hijacks a configured `ou_...` owner or rewrites `sender_open_id`; explicit `--switch-owner` / `switch_owner` switches `owner_open_id` when desired.
     - **Logout Cancellation, Pre-Start Generation Binding, & Truthful Deletion (`R2a`/`R2b`/`C2-4`)**: `start_login()` and `poll_login()` capture store/manager generations *before* initiating HTTP requests so concurrent `logout()` calls cancel both in-flight QR init (`start_login`) and in-flight QR poll (`poll_login`); `clear()` invalidates in-memory state and propagates `OSError` (surfacing HTTP 500) if `unlink()` fails.
     - **Transient vs. Definite Auth Rejection & Credential Fingerprint Binding (`C2-3`)**: `ticket()` and `profile()` raise `FeishuWebSignedOutError` only on definite auth rejection (HTTP 401/403 or missing auth identity) and raise `FeishuWebGatewayError` / `FeishuWebSessionError` on transient HTTP 5xx or malformed responses without wiping stored credentials; `mark_invalid(session=...)` and `save(..., expected_fingerprint=...)` bind invalidation and profile writeback to `FeishuWebSession.credential_fingerprint()` so stale in-flight 401 responses cannot disable a newly saved replacement session.
     - **Authoritative Namespace Normalization & Effective Transport Consistency (`R3`/`C2-1`/`C2-2`)**: Removed heuristic content/time message guessing and cross-namespace instruction suppression so distinct commands with identical text across topics or within 30s are never misrouted or dropped; unified effective transport selection via `FeishuUserClient.should_use_web_session()` across normalization, Frontier WS intake, context reads, reactions, and replies (preserving `om_`/`oc_` IDs end-to-end when `auto` mode has `im:message.send_as_user`, and never catching `FeishuDeliveryUncertainError` for fallback).
     - **Group Topic Intake & Frontier Listener (`R4`)**: `list_messages_page(container_id_type="chat")` pulls active topic threads (`PullThreadsByIDsRequest` + `PullThreadMessagesByPositionsRequest`) so `/ai` replies inside group topics are discovered and answered in-thread; `FeishuAiPoller` also wires `FeishuWebFrontierListener` (`handle_pushed_web_message`).
     - **Recursive Protobuf Merge, Whole-Value Map Entry Replacement, & Independent Wire Goldens (`R5`/`C2-5`)**: `codec.decode()` recursively merges split occurrences of singular embedded messages (`into=existing`) while replacing whole values on duplicate keys across separate map entries (`target_map[mk] = mv`) per protobuf wire spec, verified against `google.protobuf` wire golden vectors.

2. **Feishu `/ai` Transport Selection (`send_mode`), UI Status, & CLI / API Lifecycle**:
   - Added `send_mode` (`"auto"` | `"web_session"` | `"openapi"`, default `"auto"`) to `FeishuAiCommandConfig`, `feishuBotConfig.ts`, and `FeishuBotSettingsDialog.vue` (displaying truthful `Web session ready` / `Ready (web session)` status when `has_send_as_user_scope` is false).
   - In `"auto"` mode, `FeishuUserClient` and `evaluate_scope_preflight()` automatically select `web_session` when an owner-compatible web session is active and OpenAPI `im:message.send_as_user` is absent (or when no OpenAPI token is configured), while preserving existing OpenAPI + `bot_fallback` behavior when `web_session` is unconfigured or `send_mode="openapi"`.
   - Added REST API endpoints under both `/api/feishu/bot/ai-command/web-session/*` and `/api/feishu-bot/ai-command/web-session/*` (`GET status`, `POST login/start`, `POST login/poll`, `POST import-larkx`, `POST logout`) and CLI commands (`claude-hub feishu ai-command web-login [--switch-owner]`, `web-status`, `web-logout`, and `configure --send-mode`).
