# Chat 历史问答优先与过程按需加载

## 用户确认的范围

- 默认加载历次用户问题、助手回复、附件和必要状态。
- 思考、工具、子 Agent 过程默认折叠；点击时从后端按需读取。
- 不删除原始事件，不改变实时回复、待确认审批、失败/中断、编辑和 fork 语义。
- 本次只交付独立功能分支与验证，不合并、推送或重启共享服务。

## 前后端共同契约

### 历史摘要

复用现有两个 `/stream/events` GET 路由，增加 `view=conversation` 查询参数；未传该参数时保持原始协议和现有 `compact` 行为。

摘要页沿用 `AgentStreamEventPage` 的 `events`、`next_sequence`、`has_more`，增加可选、默认空列表的 `history_details`：每项含 `turn_id`、`first_sequence`、`last_sequence`、`event_count`。事件数量是该轮描述范围内的完整原始事件数，描述仅对包含省略过程的轮次出现。这些字段属于派生信息，不写回原始事件。

另外增加默认空列表 `attributed_tool_ids`，包含该页覆盖范围内已归属稳定轮次的工具/审批身份。摘要按历史顺序过滤之后重复出现的无轮次记录；不能按最终身份集合追溯删除“先无轮次、后归属”的早期合法记录。前端累计缓存这些身份，仅在新增实时事件提交时按顺序维护和过滤重复；详情回放和历史本身不使用整页身份集合重新过滤，原始实时游标仍推进。

- 保留用户问题、主线程回复、附件描述、主线程状态、错误和审批/生命周期事件。
- 从默认正文中排除思考、工具参数/结果、子 Agent 的详细过程。
- 仍需保留可操作的审批和失败状态，不得因折叠而隐藏必要操作。
- 优先优化有稳定 `turn_id` 的历史；缺少稳定轮次标识的旧事件保留兼容行为，前端仍默认折叠其过程，不猜测所属轮次。
- `next_sequence` 始终是覆盖到的原始事件游标。即使这一范围内没有问答正文，也必须推进游标并带回变化的详情描述。
- 摘要先使用可重建的进程内索引，追加时只处理文件新增部分；原始文件替换、清空或缩短时失效。复用事件存储的锁和生命周期，不创建另一个事实来源。
- 分页必须有界；不能通过每页从文件开头完整扫描来实现过滤。

### 按轮次读取详情

继续使用原 GET `/stream/events`，新增 `turn_id=<id>` 和 `through_sequence=<固定上界>`。此路径不与 `view=conversation` 混用；返回该轮在上界以内的完整事件（包含问答和过程），支持既有 `since_sequence`、`limit`、`compact=true` 分页。

- 请求中的上界固定为用户展开时已知的历史范围，避免加载期间持续追加导致分页无法结束。
- 保留来源会话鉴权、托管会话生命周期保护和路径隔离。
- 返回原始游标，既有未使用新参数的客户端行为不变。

### 前端状态归属

- `useAgentStream` 仍负责传输、原始游标和代次取消；详情读取不得推进实时游标。
- 摘要的详情描述按轮次保存，随进程内历史缓存一起保留。
- 展开时读取完整轮次，按原始序列替换该轮对应历史范围的摘要表示，而不是把旧详情注入实时序列缓冲器。
- 替换时保留请求上界之后的实时事件；不要把 compact 表示和相同范围的原始事件重复合并。
- 切换、停止、重试、删除后，旧详情响应不得更新新会话或已失效的状态。
- 同一轮并发点击去重；加载状态、错误和重试可见；加载后再次折叠展开不重复请求。
- 缓存恢复后如展开范围已有新历史，按最新描述补齐；完整性与实时状态不能依赖“轮次已完成”的假设。
- 每轮问答始终可见，过程放在独立折叠区域；未完成审批和关键错误不受该区域遮挡。

## 验证要求

- 后端：原始协议不变；摘要排除大载荷；主正文、附件、审批及错误保留；有界分页、全隐藏尾页、追加、替换、清空、轮次交错、固定上界、会话隔离和取消。
- 前端：摘要首屏、点击前无详情请求、展开恢复正确、折叠缓存、加载失败重试、切换迟到响应、上界之后的实时事件、游标不变、审批/错误、历史编辑/fork。
- 浏览器：真实 Vue 渲染、mock API，无共享服务写操作；验证默认问答和展开行为。
- 性能：使用此前保存的真实历史副本离线比较响应体积及首次/再次读取；合成类似形态用于可提交的回归样本，不提交私人会话正文。
- 再跑统一验证入口与独立审查，明确浏览器、逻辑测试及外部服务的证据边界。

## 分工

后端实现与测试由 backend 实现者负责；前端实现与单测由 frontend 实现者负责。主线程负责环境、浏览器集成、文档、性能对比和最终验收。接口需要变更时先向主线程说明理由，再同步另一实现者，不各自修改协议。

## 性能取证方法

使用任务专属目录中的一段实际历史副本，原始记录有 32,566 个事件、19 轮问答。没有把正文或工具输出提交到仓库，也没有向共享服务发送消息。

在同一个 Python 3.11.16 环境、同一份 JSONL 上比较完整 compact 读取与 conversation 读取，单页上限均为 5000；JSON 序列化和 gzip 级别 9 分别计时。每轮新建索引，再用同一实例测一次已建立索引的读取。文件系统缓存未清空，因此首次索引读取不等同于冷磁盘测试。

包含防重身份后的结果：

| 项目 | 完整 compact 历史 | 默认问答历史 |
| --- | ---: | ---: |
| 响应页数 | 7 | 2 |
| 正文事件数 | 17,673 | 82 |
| JSON 总字节 | 25,630,962 | 316,348 |
| gzip 总字节 | 5,334,947 | 154,777 |
| 首次索引读取，三次合计范围 | 1.109–1.126 秒 | 0.294–0.305 秒 |
| 已建立摘要索引后的读取 | 不适用 | 约 0.010–0.015 秒 |

问答响应包含 6746 个防重身份，因此没有采用缺少该兼容信息时更小的初版数字。客户端只在收到新实时事件时使用这些身份做去重。

Node 离线测试使用实际 reducer，比较解析、按页追加和首次分组，不包含 Vue DOM。完整历史 JSON 解析约 55–91 毫秒、reducer 约 22–35 毫秒；问答历史解析约 0.4–2.0 毫秒、reducer 约 0.1–1.7 毫秒。数组复制本身很小，本轮没有为此增加新的批处理框架。

这些是离线局部基准，不是线上浏览器端到端耗时或生产 P95。浏览器验收另行检查真实 Vue 渲染、点击、失败重试和切换行为。
