## Solution

1. **Provider-Linked Logical Model Selector & Synced `reasoning_effort` (`FeishuBotSettingsDialog.vue`, `feishuBotConfig.ts`, `feishu_ai_command_models.py`, `feishu_ai_command.py`, `api/routes/feishu_bot/ai_command.py`)**:
   - Added `provider_model_options` (`StreamModelOption` catalog per provider across `claude`, `codex`, `traex`, `maso`, `cursor`, and `antigravity`) via `capabilities_dict()` / `acapabilities_dict()` with fast warm-cache reads, a bounded `0.8s` MASO catalog probe, and curated logical fallbacks.
   - Added `gemini-example-model-1d11bad5f3fe` and `example-model-dedfefd51120` to `_MASO_MODEL_VARIANTS`, added `max` and `ultra` to `PROVIDER_SUPPORTED_REASONING_EFFORTS["codex"]` / `["traex"]`, and placed non-exhausted MASO logical defaults ahead of `gemini-example-model-1dd583607df6` while retaining full backward compatibility.
   - Replaced `<input data-testid="feishu-ai-model-input">` in `FeishuBotSettingsDialog.vue` with a Provider-linked `<select data-testid="feishu-ai-model-input">` displaying clean logical model options (without duplicating `_reasoning_*` variant rows), mapping persisted variant IDs (e.g. `gemini-example-model-1dd583607df6_reasoning_high`) without mutating `aiEdit.model` on hydration (`tupleDirty` stays `false`), preserving unlisted custom/current models (`<id> (custom/current)`), and syncing `aiEffortOptions` + disabling `<select data-testid="feishu-ai-effort-select">` when unsupported.
   - Aligned both per-model live MASO `mode="default"` (`example-model-75c87952ca70`, `example-model-051bc3aafde0`, `gpt-example-model-d050a243e4ed`, `example-model-dedfefd51120`, `example-backend` + dynamic live catalog variant sync via `register_live_maso_model_variants`) and empty-model `Provider default` (`model=""`) normalization across frontend and backend (`validate_ai_command_agent_config`, `FeishuAiCommandService.update_config`, `parse_ai_command`, and `FeishuBotSettingsDialog.vue`): MASO `mode="default"` resolves to the base `provider_model_id` (e.g. `("maso", "example-model-dedfefd51120", "default")`), non-MASO `"default"` normalizes to `""`, and empty `model=""` clears `reasoning_effort` to `""` on model-bound effort providers (`maso`, `cursor` -> `(provider, "", "")`) while `ENV_KEY` providers (`codex`, `traex`) preserve `(provider, "", effort)`. Explicit per-message `--effort` flags in `parse_ai_command` on a `Provider default` MASO/Cursor config resolve against `DEFAULT_PROVIDER_MODELS[provider][0]`.
2. **Live `/ai` Discovery, Authoritative Cross-App WS Verification & Safe `230002` Fallback (`feishu_user_client.py`, `feishu_ai_poller.py`, `feishu_ai_command.py`, `feishu_bot.py`)**:
   - Updated `FeishuUserClient.list_chats()` to pass `types="p2p,group"` by default and added `search_messages_page()` + `from_ids` / `page_token` support on `search_messages()`.
   - Added `_discover_recent_owner_command_chats()` in `FeishuAiPoller.poll_once()` when `watch_chats` is empty: filters already-completed (`recent_runs`), queued (`pending_commands`), in-flight (`_in_flight_ids`), watermarked, and cached non-owner message IDs BEFORE consuming the per-tick `get_message()` / chat-discovery budget, and paginates across up to `_MAX_SEARCH_PAGES_PER_POLL = 5` search pages so subsequent ticks deterministically advance beyond processed/known hits.
   - Added `_verify_cross_app_ws_owner()` in `FeishuAiCommandService.handle_ws_event()`: when an enabled `/ai` candidate arrives over WebSocket with a different app's `sender_open_id`, Hub fetches `event.message_id` via `user_client.get_message()` under `cfg.app_id` and verifies `fetched.sender_type == "user"` and `hmac.compare_digest(fetched.sender_open_id, cfg.owner_open_id)` — zero display-name or unverified binding-alias matching.
   - Added `receive_id_type` support (`chat_id` default, `open_id` for owner DM) in `FeishuBotClient.send_message_with_identity()` and opt-in `allow_bound_or_dm_fallback_on_not_in_chat=True` on `/ai` replies (`_reply_ai_command()`): ONLY on definite Feishu `230002` (`bot not in chat`) — never on post-accept timeouts or `FeishuDeliveryUncertainError` — `_reply_via_bot_fallback()` / `_send_via_bot_fallback()` first tries an enabled non-tombstoned `FeishuBotPoolStore` bot bound to `chat_id`, and otherwise delivers via direct message to `record.open_id` (`receive_id_type="open_id"`) using the primary fallback bot (`record.app_id == bot_app_id`). Low-level `reply_as_user()` / `send_as_user()` keep `auto_invite_bot_to_chat=False` and `allow_bound_or_dm_fallback_on_not_in_chat=False` by default.
